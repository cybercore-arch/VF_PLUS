# Как написать паттерн атаки

Паттерн — это отдельный `.gd` файл. Один файл — один паттерн. Наследование не требуется: менеджер вызывает метод `execute` напрямую у любого загруженного скрипта.

## Где лежат паттерны

- **Встроенные** — `res://entites/attacks/`. Попадают в сборку.
- **Внешние** — папка `patterns/` рядом с исполняемым файлом. Загружаются во время выполнения.

Приоритет у внешних: если в `patterns/` есть файл с тем же именем, что и встроенный, загрузится внешний.

## Контракт

Каждый паттерн обязан иметь метод:

    func execute(arena, params: Dictionary) -> void:

- `arena` — сцена арены. Через неё получаешь игрока, добавляешь пули, проверяешь паузу и смерть.
- `params` — словарь параметров из JSON. Читай через `params.get("ключ", значение_по_умолчанию)`.

Если хочешь, чтобы паттерн был доступен в `random`, он должен корректно работать с пустым `params` и не падать.

## Минимальный пример

    extends Node

    const BULLET_SCENE = preload("res://entites/bullet.tscn")

    func execute(arena, params: Dictionary) -> void:
        var angle: float = params.get("angle", 0.0)
        var speed: float = params.get("speed", 200.0)
        var color = params.get("color", Color.WHITE)

        var dir := Vector2.RIGHT.rotated(deg_to_rad(angle))
        var bullet = BULLET_SCENE.instantiate()
        bullet.setup(arena.player.global_position, dir * speed, color)
        arena.add_child(bullet)


## Как менеджер обрабатывает параметры

Перед вызовом `execute` PatternManager прогоняет `params` через две вещи:

1. **`_maybe_color`** — если значение параметра массив из 3 или 4 чисел, оно превращается в `Color`. Формат: `[r, g, b]` или `[r, g, b, a]`, каждое число от 0.0 до 1.0.
2. **`resolve_param`** — только для поля `pos`. Строковые значения заменяются на вектор:
   - `"center"` — центр экрана.
   - `"random"` — случайная точка с отступом 50 пикселей от краёв.
   - `"player"` или `"aimed"` — позиция игрока. Если игрок не найден — центр экрана.
   - Массив из двух чисел — `Vector2(x, y)`.

Другие поля через `resolve_param` не проходят. Если паттерну нужна позиция в другом поле (например `spawn`), он должен сам вызвать `resolve_param` или получить готовый вектор.

## Общие правила

1. **Проверяй, что арена жива.** Долгие паттерны должны прекращать работу, если игрок умер или уровень перезапущен.

       if not is_instance_valid(arena) or arena.is_dead:
           return

2. **Уважай паузу.** Если у арены есть флаг `paused` или аналогичный, долгие циклы должны его проверять и приостанавливаться.

3. **Для задержек используй `await get_tree().create_timer(t).timeout`**, а не счётчики в `_process`. Так паттерн сам завершается и не течёт.

4. **Не держи ссылку на арену после завершения.** После выхода из `execute` объект паттерна больше никто не использует.

5. **Если паттерн загружает другой скрипт** (как `loop` или `random`) — проверяй `has_method("execute")` перед вызовом. Иначе краш, если в папке окажется кривой файл.


## Композиция

`loop` и `random` не спавнят пули сами. Они загружают другой скрипт и вызывают его `execute`. Если пишешь свой мета-паттерн — следуй тому же правилу: проверяй `has_method("execute")` перед вызовом.

## Безопасность внешних паттернов

Файлы из `patterns/` выполняются с полными правами игры. Не клади туда чужие `.gd`, если не доверяешь источнику. 

## Отладка

- **Паттерн не вызывается** — проверь, что имя файла совпадает с `pattern` в JSON, и что файл лежит в `entites/attacks/` или в `patterns/`.
- **Пули летят не туда** — распечатай входные `params` через `print(params)`.
- **Паттерн не останавливается при смерти игрока** — забыл проверку `arena.is_dead` внутри цикла.
- **Параметр не тот** — проверь, что для `pos` используется именно `pos`, и что цвет задан массивом, а не строкой (строки `_maybe_color` не обрабатывает).
